# ODM 测试报告与问题复盘模板库

## 测试报告结构模板
标题：项目 / 版本 / 模块测试报告
1. 测试背景：说明项目、版本、模块和测试目标。
2. 测试范围：列出覆盖功能、设备、网络、外设和版本组合。
3. 执行概况：用例总数、通过数、失败数、阻塞数、通过率。
4. 关键问题：按严重级别列出缺陷、影响范围和当前状态。
5. 风险说明：说明未覆盖范围、阻塞原因和发布建议。
6. 附件：日志、截图、录屏、测试记录和缺陷单链接。

## 缺陷复盘模板
1. 问题现象：用户可感知或测试可复现的表现。
2. 影响范围：项目、版本、机型、模块、概率和场景。
3. 复现步骤：前置条件、操作路径、复现频次。
4. 日志证据：关键日志时间点、错误码、堆栈或状态变化。
5. 初步原因：仅写已有证据支持的判断。
6. 临时规避：可执行的临时方案和适用限制。
7. 后续动作：责任模块、验证计划、待补充信息。

## 版本回归验证模板
1. 修复内容：缺陷编号、修改点、关联提交或版本说明。
2. 验证环境：机型、软件版本、外设、网络和账号条件。
3. 验证步骤：按照原始复现路径和扩展场景执行。
4. 验证结果：通过、未通过、阻塞或需进一步确认。
5. 证据附件：日志、截图、录屏和测试记录。
6. 遗留风险：未覆盖场景和建议补充测试。

## 蓝牙问题测试报告示例结构
测试目标：验证 X100 蓝牙扫描、配对、连接、回连和音频链路稳定性。
重点数据：设备型号、对端设备、连接距离、回连间隔、失败概率、HCI 日志。
关键风险：兼容性设备覆盖不足、低功耗状态回连时序异常、对端缓存导致误判。

## ANR 复盘输出结构
必须包含进程名、发生时间、主线程堆栈、CPU 状态、Binder 或锁等待信息、用户操作路径、影响范围、待补充 traces 或 bugreport。
